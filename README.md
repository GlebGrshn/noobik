# Нубик Шахтёр: копай глубже

Первый прототип Unity для Яндекс Игр. Репозиторий: https://github.com/GlebGrshn/noobik

## Открыть игру

1. Unity Hub → **Add → Add project from disk** → выбрать папку `noobik`.
2. Открыть в **Unity 6000.6.3f1**. Используется URP 17.6.0.
3. Открыть `Assets/Game/Scenes/Mine.unity` и нажать **Play**.
4. Если сцены ещё нет: меню **Nubik → Prepare prototype** создаст её и конфигурацию.

Управление на ПК: клик по экрану захватывает мышь; мышь — осмотр, ЛКМ — копать, WASD — ходить, пробел — прыжок, R — наверх (лавка), E — лавка рядом с прилавком, M — звук, Esc — отпустить мышь. Если браузер не даёт захватить мышь, осмотр — с зажатой ПКМ. На телефоне — стик слева, обзор пальцем справа, кнопки «КОПАТЬ» и «ПРЫЖОК».

## Что входит в прототип

- Вид от первого лица: двор с домом, газоном и лавкой, участок 12 × 12 м, который можно раскопать до 120 м.
- Сплошной деформируемый грунт (воксели 0,5 м, сглаженная поверхность), три зоны: земля (0–30 м), камень (30–70 м), пещера с полостями (70–120 м), на дне — зал с запечатанной дверью и финальная панель.
- Монеты за вынутый грунт, находки и сундуки в рюкзак (продаются в лавке), 5 предметов коллекции с альбомом.
- Четыре лопаты: обычная, медная (60), стальная (220), кристальная (700).
- Свет и туман по глубине, налобный фонарь, частицы, всплывающие суммы и синтезированные звуки.
- Локальное версионированное сохранение v2 с резервной копией и миграцией сохранений прототипа v1.
- WebGL-шаблон, базовые события готовности / геймплея SDK, пауза при потере фокуса.

Это сборка для проверки механики, не версия для модерации. Реклама, облачные сохранения, английский язык и аналитика ещё не реализованы; графика — временные примитивы.

## Настройки и проверка

Баланс: `Assets/Game/Config/MineBalance.asset` — seed, размеры участка, зоны (прочность, доход, находки, свет), лопаты, коллекция, скорость. Менять seed в существующем сохранении нельзя без миграции: прототип сохранит старые данные и откроет временную сессию.

Тесты: **Window → General → Test Runner → EditMode → Run All**. Командная проверка: `Tools/Check.ps1`. Проверяются повторные выплаты, покупка, коллекция, сериализация прогресса и грунта, миграция, прочность пород и генерация находок. Звуки пересоздаются командой `py -3 Tools/make_sounds.py`.

Снимки глубин: PlayMode-тест `DepthSnapshots` запускает сцену, опускает игрока на 12, 45, 90 и 120 м и сохраняет кадры в `TestResults/Snapshots`. Запускать с графикой (без `-nographics`): `Unity.exe -batchmode -projectPath . -runTests -testPlatform PlayMode`. Локальное сохранение редактора на время теста откладывается и восстанавливается.

WebGL: установить **Web Build Support** для закреплённой версии Unity и выбрать **Nubik → Build WebGL**. Результат — `Builds/WebGL`, открыть через HTTP, а не `file://`. Пример: `py -3 -m http.server 8080 --directory Builds/WebGL`, затем http://localhost:8080. Для консоли Яндекс Игр упаковывается содержимое этой папки, с `index.html` в корне архива. Перед загрузкой требуется пройти `Docs/Development.md`.

## Работа с GitHub

Исходники, `.meta`, сцены, настройки и документы хранятся в Git. `Library`, `Temp`, сборки, логи и личные настройки игнорируются. После завершённого изменения: проверка → осмысленный commit → push. Публичный репозиторий не должен содержать ключей SDK, лицензий Unity и пользовательских сохранений. Blender-файлы добавляем в `Art/Source`, экспорт для Unity — в `Assets/Game/Art`.

Исходные дизайн-документы находятся в `Docs`. Они описывают проект и гипотезы баланса; факт готовности функции отражается в `Docs/Development.md`.
